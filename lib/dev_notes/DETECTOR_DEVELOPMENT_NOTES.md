# ملاحظات تطوير خدمة الكشف (DetectorService)

## شكل الموديل المؤكَّد
- **المُدخل**: `[1, 416, 416, 3]` float32 → NHWC، بقيم خام 0..255.
- **المُخرج**: `[1, 85, 3549]` float32 → `[1, 5+80 فئة, عدد الصناديق]`.
- **عدد الصناديق**: 3549 = 52×52 + 26×26 + 13×13.

## خصائص المخرجات
- لكل صندوق: `[cx, cy, w, h, objectness, classScore0, classScore1, ...]`.
- الثقة النهائية = objectness × أعلى classScore.
- الموديل لا يطبّق فك تشفير الشبكة → نحتاج `decodeRawGrid()`.

## تحسينات الأداء المطبقة
1. **تخطي مبكر**: تخطي فحص الفئات إذا كان `objectness < threshold`.
2. **XNNPack**: تسريع CPU (أأمن من GPU في هذه الحالة).
3. **تسطيح المخرجات**: استخدام `Float32List` بدلاً من القوائم المتداخلة.
4. **NMS مرحلتين**: الأولى لنفس التسمية، الثانية عبر التسميات (عتبة 0.75).

## لماذا `_manualGridDecodeRequired = true`؟
- الموديل لا يفك تشفير الشبكة، يعطي إحداثيات خام نسبية لكل خلية.

## لماذا تم إلغاء استخدام compute()؟
- نقل البيانات (~1.2 ميجابايت) يسبب عبئاً وتراكم ذاكرة.
- تحسين "التخطي المبكر" جعل الفك خفيفاً كفاية للعمل على الخيط الرئيسي.

## لماذا `detectionHoldFrames = 2`؟
- `0`: اختفاء فوري.
- `2`: حل وسط بين الاستجابة السريعة واستقرار العرض.

## ملاحظة حول أداء البطارية ⚠️
- وضع توفير الطاقة أو انخفاض الشحن يؤدي إلى خفض تردد المعالج، مما يزيد زمن الاستدلال بشكل ملحوظ.
- تأكد من أن الجهاز في وضع الأداء العالي أثناء الاختبار لتحقيق أفضل أداء (~800ms مع XNNPack).
- مع البطارية الضعيفة، قد يرتفع زمن الاستدلال إلى 1200-2000ms أو أكثر.

## مسار التصدير (PyTorch → TFLite)
1. PyTorch (.pth) → ONNX (export_onnx.py, Python 3.10, torch 1.13.1).
2. ONNX → TFLite (onnx2tf).
3. ضع الملف في `assets/models/model.tflite`.

## التراخيص
- YOLOX: Apache-2.0.
- XNNPack: جزء من TensorFlow Lite (Apache-2.0).
